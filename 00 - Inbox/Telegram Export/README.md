# Telegram Channel Export

Экспорт каналов из папки **🌐** для персональной очереди чтения. По умолчанию сохраняются последние **35 публикаций каждого канала**, от новых к старым. Альбом с несколькими вложениями считается одной публикацией. Дальнейший анализ применяет правило **5 → ещё 30**; наличие поста в выгрузке не означает, что он прочитан или рекомендован.

## Запуск

В своём терминале выполни:

```bash
bash '/Users/grishinid/home/02_SecondBrain/public/00 - Inbox/Telegram Export/run.sh' --expect-channels 33
```

При первом запуске установится Telethon в отдельное окружение `.venv`. Нужны Python 3.10+ и доступ к PyPI и Telegram.

Скрипт запросит `api_id`, `api_hash`, номер нужного аккаунта, код входа и пароль 2FA, если он включён. `api_hash`, код и пароль вводятся скрыто: отсутствие символов на экране нормально. Данные вводи в своём терминале, не в чате с моделью. **Каждый запуск требует нового входа:** сессия живёт только в памяти процесса.

Сначала выводятся подтверждённое имя папки и полный список её каналов, затем прогресс. Если вместо 33 найдено другое количество, появится предупреждение; фактический состав сохранится в JSON. При совпадении имён папок скрипт покажет их ID; повторный запуск с `--folder-id ID` выбирает конкретную папку.

В конце скрипт запросит выход из временной сессии и при подтверждении Telegram напечатает об этом. Затем появится полный путь к JSON в `exports/`. Передай модели **только этот JSON или путь к нему**. Ошибки отдельных каналов сохраняются явно; частичная выгрузка получает статус `partial`. При прерывании уже завершённые каналы остаются в JSON со статусом `in_progress`; незавершённые имеют статус `pending`.

В JSON поле `session_cleanup.status` показывает результат выхода: `revoked` — Telegram подтвердил отзыв сессии, `unconfirmed` — подтверждения нет, `pending` — завершение ещё не записано. Это отдельный статус от полноты выгрузки.

## Что сохраняется

- Состав выбранной папки: названия каналов, ID, публичные ссылки и ошибки определения состава.
- Полный текст и подписи постов, даты публикации и редактирования, ссылки на посты и внешние источники, включая ссылки под текстом и на кнопках.
- Типы вложений, имена файлов, известная длительность аудио/видео, вопросы опросов и доступные превью ссылок.
- Указатели на исходный канал перепечатки, когда они присутствуют в метаданных Telegram.

Выгружаются только каналы. Для ручной или общей папки разрешаются явно включённые каналы и группы, чтобы отличить канал от группы; личные чаты и боты не открываются. Если включено динамическое правило «все каналы», дополнительно читается список диалогов для вычисления состава; прочие диалоги не записываются в JSON. Учитываются закрепления, явные исключения и серверные признаки архива, непрочитанности и отключённых уведомлений. Локальное временное состояние другого клиента может отличаться от серверного снимка.

## Где лежат данные

- **Сессия:** `MemorySession`, только в памяти процесса. Файл `.session` и строка авторизации не создаются. Сохранённые сессии прежней версии не загружаются.
- **API-реквизиты:** по умолчанию не сохраняются. При необходимости можно передать их через `TG_API_ID` и `TG_API_HASH`, но не вводить значения прямо в командную строку с историей shell.
- **Выгрузка:** `exports/`, исключена из Git. Создаются новые файлы с уникальными именами, существующие выгрузки не перезаписываются.
- `.venv`, `.env*`, файлы сессий и Python-кэш в этой папке также исключены из Git.

Для экспорта скрипт выполняет запросы чтения; при завершении отправляет `auth.logOut` для отзыва своей временной авторизации. Он не отправляет сообщения, не отмечает историю прочитанной и не меняет папки, подписки или настройки. Медиафайлы, внешние статьи и расшифровки видео не скачиваются; их проверка — отдельный этап анализа. Превью Telegram не является проверкой источника.

## Завершение сеанса

Выход выполняется и после ошибок, при Ctrl+C и обычном SIGTERM. На подтверждение даётся до 15 секунд. При отсутствии подтверждения скрипт явно предупреждает, сохраняет `unconfirmed` в JSON и завершается с ошибкой; отключение от сети не выдаётся за отзыв доступа.

При SIGKILL, повторном принудительном прерывании, потере питания или недоступности Telegram выполнить выход может быть невозможно. Тогда заверши **только сеанс Telegram Reading Export** через **Telegram → Настройки → Устройства** на уже авторизованном телефоне.

Если запускалась прежняя версия, её файл `~/.local/state/telegram-reading-export/account.session` может оставаться на диске. Новая версия проверяет только наличие файла и предупреждает, не открывая его содержимое. **Прежний сеанс нужно отдельно завершить через «Устройства»**: новый вход и его автоматический выход не отзывают старую авторизацию. Удаление локального файла тоже не отзывает её на сервере.
