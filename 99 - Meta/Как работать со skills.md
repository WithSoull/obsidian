# Как работать со skills

## Зачем это нужно

Skills помогают быстрее переводить меня в нужный режим работы.
Чем точнее ты задаёшь роль, тем меньше времени уходит на уточнения и тем стабильнее результат.

## Какие skills есть

- `tech-book-note-generator` — сделать учебную заметку из отрывка книги, статьи, лекции, RFC или документации.
- `note-fact-reviewer` — проверить заметку на фактические ошибки, опасные упрощения и слабые объяснения.
- `note-practical-enricher` — добавить в заметку практические детали: примеры, trade-offs, production cases, failure modes, debugging.
- `note-revision-coach` — провести активное повторение через вопросы и проверку ответов.
- `note-link-weaver` — найти и добавить полезные Obsidian-связи между заметками.

## Как вызывать

Можно явно через имя skill:

```text
$tech-book-note-generator сделай заметку из этого отрывка
$note-fact-reviewer проверь эту заметку
$note-practical-enricher дополни заметку практикой
$note-revision-coach погоняй меня по этой теме
$note-link-weaver свяжи эту заметку с другими
```

Можно естественным языком, без `$...`, если задача сформулирована достаточно чётко:

- Сделай учебную заметку из этого фрагмента книги.
- Проверь заметку на ошибки и слабые места.
- Добавь practical nuance и примеры из backend.
- Позадавай мне вопросы по этой заметке.
- Найди и добавь полезные wikilinks.

## Лучшие сценарии

### 1. Создать новую заметку из источника

Цепочка:

`tech-book-note-generator -> note-fact-reviewer -> note-practical-enricher -> note-link-weaver`

Когда использовать:

- есть отрывок из книги или статьи
- нужно быстро превратить его в хорошую заметку
- хочется сразу встроить заметку в vault

Пример запроса:

```text
$tech-book-note-generator
Вот отрывок из книги. Сделай из него заметку для Obsidian на русском.
Фокус: Go backend, distributed systems.
Папка: 30 - Learning
```

### 2. Улучшить уже существующую заметку

Цепочка:

`note-fact-reviewer -> note-practical-enricher -> note-link-weaver`

Когда использовать:

- заметка уже есть
- нужно убрать ошибки и двусмысленность
- нужно сделать её полезнее для реальной инженерной работы

Пример запроса:

```text
$note-fact-reviewer
Проверь эту заметку. Нужны фактические ошибки, слабые формулировки и опасные упрощения.
Если всё нормально, скажи, где именно заметка уже сильная.
```

### 3. Закрепить тему после чтения

Цепочка:

`note-revision-coach`

Когда использовать:

- заметка уже приведена в порядок
- нужно проверить, что тема действительно усвоилась
- хочется не перечитывать пассивно, а вспоминать активно

Пример запроса:

```text
$note-revision-coach
Погоняй меня по этой заметке.
По одному вопросу за раз.
Если отвечаю неполно, коротко поправь и иди дальше.
```

## Что лучше указывать в запросе

Чтобы результат был лучше, полезно сразу передавать:

- цель: сделать заметку, проверить, дополнить, связать, погонять по теме
- источник: текст, путь к заметке, название темы
- глубину: кратко, средне, глубоко
- фокус: Go, storage, networking, concurrency, distributed systems
- режим: только предложить изменения или сразу внести их

## Практические шаблоны

### Сделать заметку из источника

```text
$tech-book-note-generator
Преобразуй этот отрывок в короткую учебную заметку.
Пиши на русском.
Добавь пример из backend, если он реально помогает.
```

### Проверить заметку

```text
$note-fact-reviewer
Проверь заметку как technical review.
Интересуют:
- фактические ошибки
- двусмысленность
- missing nuance
- опасные упрощения
```

### Добавить практический слой

```text
$note-practical-enricher
Усиль заметку практикой.
Добавь:
- trade-offs
- failure modes
- debugging hints
- production examples
Без лишней теории.
```

### Добавить связи

```text
$note-link-weaver
Найди для этой заметки только действительно полезные связи.
Если связь неочевидная, коротко объясни, почему она полезна.
```

### Повторить тему

```text
$note-revision-coach
Задавай вопросы по заметке.
Хочу проверку на понимание, а не пересказ текста.
```

## Рекомендуемый стиль работы

Для новых тем:

`generator -> reviewer -> enricher -> link-weaver`

Для старых заметок:

`fact-reviewer -> practical-enricher -> link-weaver`

Для закрепления:

`revision-coach` после того, как заметка уже стала точной и полезной.

## Важный принцип

Лучше короткий, но явно заданный режим работы, чем общий запрос.

Плохо:

```text
Посмотри заметку
```

Лучше:

```text
$note-fact-reviewer проверь заметку на фактические ошибки и слабые объяснения
```

Ещё лучше:

```text
$note-fact-reviewer
Проверь заметку на фактические ошибки, двусмысленность и опасные упрощения.
Если нужно, сразу исправь текст.
Фокус на backend и distributed systems.
```
