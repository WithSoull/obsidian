# Метрики качества ML-моделей — объяснение для бэкендера

> **Контекст:** все метрики использованы в ПР4 ПИНТС. Регрессия: RMSE, MAE, R². Классификация: Accuracy, F1.

---

## Метрики регрессии

Регрессия предсказывает числа. Метрики измеряют, насколько близко предсказание к реальному значению.

---

### RMSE — Root Mean Squared Error

```
RMSE = √(Σ(yᵢ - ŷᵢ)² / n)
```

**Простыми словами:** "средняя ошибка предсказания, при этом большие ошибки штрафуются сильнее".

**Пошаговый пример:**
```python
y_true = [600, 1200, 300, 900]   # реальные длительности (сек)
y_pred = [700, 1000, 400, 800]   # предсказанные

# Шаг 1: Ошибки
errors = [700-600, 1000-1200, 400-300, 800-900]
#       = [+100,   -200,       +100,   -100]

# Шаг 2: Квадраты ошибок
squared = [10000, 40000, 10000, 10000]
# (отрицательные стали положительными, большие усилилились)

# Шаг 3: Среднее квадратов
mse = (10000 + 40000 + 10000 + 10000) / 4 = 17500

# Шаг 4: Корень
rmse = √17500 = 132 секунды
```

**Интерпретация:** модель ошибается в среднем на 132 секунды, причём ошибка в 200 с "весит" вчетверо больше, чем ошибка в 100 с.

**Единица измерения:** та же, что у целевой переменной (секунды в нашем случае).

**Зачем квадрат?** Без квадрата +100 и -100 дадут нулевую среднюю ошибку — это неправильно.

**Зачем RMSE, а не MSE?** RMSE имеет ту же размерность, что и исходные данные. MSE в секундах² — неинтерпретируемо.

**Наши результаты:**
```
Linear Regression: RMSE = 4072 с (~68 минут)   ← плохо
Random Forest:     RMSE = 309 с  (~5 минут)    ← хорошо
```

---

### MAE — Mean Absolute Error

```
MAE = Σ|yᵢ - ŷᵢ| / n
```

**Простыми словами:** "средняя абсолютная ошибка — каждая ошибка весит одинаково".

```python
errors = [+100, -200, +100, -100]
abs_errors = [100, 200, 100, 100]
mae = (100 + 200 + 100 + 100) / 4 = 125 секунд
```

**Разница между RMSE и MAE:**

```
Пример А (равномерные ошибки):
  ошибки: 100, 100, 100, 100
  RMSE = 100
  MAE  = 100
  → одинаковы

Пример Б (один выброс):
  ошибки: 10, 10, 10, 970
  RMSE = √(100+100+100+940900)/4 = √235300 ≈ 485
  MAE  = (10+10+10+970)/4 = 250
  → RMSE в 2x больше из-за выброса
```

**Когда что использовать:**
- **RMSE** — когда большие ошибки неприемлемы (медицина, финансы)
- **MAE** — когда нужна "типичная" ошибка без влияния выбросов

**Наши результаты:**
```
Linear Regression: MAE = 396 с  (~6.5 минут)
Random Forest:     MAE = 193 с  (~3 минуты)
```

MAE < RMSE всегда — это математически гарантировано.

### R² — Коэффициент детерминации

```
R² = 1 - SS_res / SS_tot

SS_res = Σ(yᵢ - ŷᵢ)²    # сумма квадратов остатков (что модель не объяснила)
SS_tot = Σ(yᵢ - ȳ)²     # общая дисперсия (разброс данных)
```

**Простыми словами:** "какую долю разброса данных объясняет модель".

**Интерпретация:**
```
R² = 1.0  → идеальная модель, объясняет 100% разброса
R² = 0.77 → модель объясняет 77% разброса (Random Forest)
R² = 0.47 → модель объясняет 47% разброса (линейные модели)
R² = 0.0  → модель не лучше предсказания среднего значения
R² < 0    → модель хуже предсказания среднего! (плохая модель)
```

**Пошаговый пример:**
```python
y_true = [600, 1200, 300, 900]
y_mean = 750  # среднее

# SS_tot: насколько данные разбросаны вокруг среднего
ss_tot = (600-750)² + (1200-750)² + (300-750)² + (900-750)²
       = 22500 + 202500 + 202500 + 22500 = 450000

# SS_res: насколько модель ошиблась
y_pred = [700, 1000, 400, 800]
ss_res = (600-700)² + (1200-1000)² + (300-400)² + (900-800)²
       = 10000 + 40000 + 10000 + 10000 = 70000

R² = 1 - 70000/450000 = 1 - 0.156 = 0.844
# Модель объясняет 84.4% разброса данных
```

**Важно:** R² не зависит от единиц измерения — безразмерная метрика. Поэтому удобна для сравнения разных задач.

**Наши результаты:**
```
Linear Regression: R² = 0.47  ← объясняет меньше половины разброса
Random Forest:     R² = 0.77  ← объясняет 77%
```

**Почему R² = 0.77 — это хорошо?** Длительность поездки зависит ещё от пробок (реального трафика), которые мы не знаем. Объяснить 77% без данных о пробках — отличный результат.

## Метрики классификации

Классификация предсказывает категорию. Другие метрики.

---

### Accuracy — точность классификации

```
Accuracy = Правильные предсказания / Все предсказания
```

```python
y_true = [GALAXY, STAR, QSO, GALAXY, GALAXY]
y_pred = [GALAXY, STAR, GALAXY, GALAXY, QSO]
#                         ^^^               ^^^
#                         ошибка             ошибка

accuracy = 3 / 5 = 0.6 = 60%
```

**Наши результаты:**
```
Logistic Regression: Accuracy = 95.46%
Decision Tree:       Accuracy = 97.50%
KNN:                 Accuracy = 96.75%
```

**Проблема Accuracy:** не работает на несбалансированных данных.

```
# Датасет: 95% — не спам, 5% — спам
# Модель всегда говорит "не спам":
Accuracy = 95%  ← выглядит отлично, но модель бесполезна!
```

---

### Матрица ошибок (Confusion Matrix)

Для понимания реальных ошибок нужно смотреть, где конкретно модель ошибается:

```
                Предсказание:
                GALAXY  STAR  QSO
Реальность:
GALAXY  [  11530    58   301 ]
STAR    [     6  4313     0  ]
QSO     [   229   273  3291  ]
```

Читаем строки = реальный класс, столбцы = предсказанный класс.  
По диагонали — правильные ответы.  
Вне диагонали — ошибки.

**Вывод:** модель путает QSO с GALAXY (229 случаев) — потому что квазары действительно похожи на галактики в оптическом диапазоне.

### Precision, Recall, F1

Когда классы несбалансированы, смотрим на три дополнительные метрики:

```
Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
F1        = 2 * Precision * Recall / (Precision + Recall)
```

Сложно? Вот аналогия через поиск:

```
Представь: ты ищешь баги в коде.
├── Нашёл 10 "багов"
│   ├── 8 реальных баги    (True Positive)
│   └── 2 не баги (ложная тревога) (False Positive)
└── Пропустил 3 реальных бага      (False Negative)

Precision = 8/10 = 80%  ← из того, что нашёл — сколько правильно
Recall    = 8/11 = 73%  ← из всех реальных — сколько нашёл
F1        = 2*0.8*0.73/(0.8+0.73) = 0.76
```

**Когда что важнее:**
- **Высокий Recall** важен когда цена пропуска высокая (онкология: лучше лишнее обследование, чем пропустить рак)
- **Высокий Precision** важен когда цена ложной тревоги высокая (спам-фильтр: лучше пропустить спам, чем удалить важное письмо)

---

### AUC-ROC (для двухклассовой задачи)

Ещё одна важная метрика — площадь под ROC-кривой. Измеряет, насколько хорошо модель **ранжирует** объекты.

```
AUC = 1.0  → идеально
AUC = 0.9  → отлично
AUC = 0.7  → приемлемо
AUC = 0.5  → случайное угадывание
AUC < 0.5  → модель инвертирует классы
```

Преимущество: AUC не зависит от порога классификации (0.5) и работает даже на несбалансированных данных.

## Сравнение всех метрик

| Метрика | Задача | Когда высокая = лучше | Единица |
|---------|--------|----------------------|---------|
| RMSE | Регрессия | ❌ (меньше = лучше) | как у y |
| MAE | Регрессия | ❌ (меньше = лучше) | как у y |
| R² | Регрессия | ✅ | — (0 до 1) |
| Accuracy | Классификация | ✅ | % |
| Precision | Классификация | ✅ | % |
| Recall | Классификация | ✅ | % |
| F1 | Классификация | ✅ | — (0 до 1) |
| AUC-ROC | Классификация | ✅ | — (0 до 1) |

## Как не ошибиться с интерпретацией

**Ошибка 1:** Смотреть только на Accuracy при несбалансированных классах  
**Решение:** Всегда смотреть на F1 и матрицу ошибок

**Ошибка 2:** Сравнивать RMSE моделей на разных данных  
**Решение:** Сравнивать только на одной тест-выборке

**Ошибка 3:** Радоваться R²=0.99  
**Решение:** Проверить, нет ли data leakage (будущие данные попали в обучение)

**Ошибка 4:** Считать метрики на обучающей выборке  
**Решение:** Всегда считать на отложенной тест-выборке
