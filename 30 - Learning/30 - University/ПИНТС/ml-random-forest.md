# Random Forest — объяснение для бэкендера

> **Контекст:** использован в ПР4 ПИНТС. Результат: RMSE=309 с, R²=0.77. Лучшая модель в эксперименте. Обучение за 3.7 с, но потребовал 37.7 MB памяти.

---

## Главная идея

Возьми 100 немного разных деревьев решений, обучи каждое на случайном подмножестве данных и признаков, потом усредни их ответы. Среднее ответов 100 "средних" деревьев точнее, чем один "умный" дерево.

Это называется **ансамблирование** и базовый принцип: **мудрость толпы**.

---

## Аналогия: код-ревью от команды

Представь, что тебе нужно оценить Pull Request. Варианты:

**Вариант А (Decision Tree):** один эксперт смотрит и даёт оценку. Быстро, но если эксперт ошибается — всё плохо.

**Вариант Б (Random Forest):** 100 разработчиков смотрят PR, каждый видит только часть файлов (случайно выбранных). Большинство говорит "одобрить" → одобряем. Один эксперт ошибётся — не страшно, остальные 99 скомпенсируют.

## Что такое Decision Tree (одно дерево)

Прежде чем понять Forest, нужно понять одно дерево.

Дерево решений задаёт вопросы по одному признаку за раз:

```
Длительность поездки?
│
├─ distance_km > 5 км?
│   ├─ ДА → hour > 8 и hour < 19?
│   │         ├─ ДА (день) → предсказание: 1200 сек
│   │         └─ НЕТ (ночь) → предсказание: 700 сек
│   └─ НЕТ (короткая) → предсказание: 400 сек
```

Это просто `if-else` в виде дерева. Для регрессии в листьях стоит **среднее** всех точек, которые туда попали.

### Проблема одного дерева: переобучение

Если разрешить дереву расти неограниченно, оно запомнит **каждую** точку обучающей выборки:

```
if distance == 3.7421 and hour == 14 and pickup_lat == 40.7589:
    return 847  # конкретное значение из обучающих данных
```

На обучающих данных — 100% точность. На новых — катастрофа.

## Три ключевых трюка Random Forest

### 1. Bootstrap Aggregating (Bagging)

Каждое из 100 деревьев обучается не на всех данных, а на **случайной выборке с повторением** (bootstrap sample).

```python
# Грубо говоря:
for i in range(100):
    sample = original_data.sample(n=len(original_data), replace=True)
    #                                                    ^^^^^^^^^^^^
    #              replace=True: одна строка может попасть несколько раз
    tree_i.fit(sample)
```

Примерно 63% строк попадут в каждое дерево (остальные 37% — Out-of-Bag, используются для оценки качества без тест-выборки).

**Результат:** деревья видят разные данные → разные ошибки → при усреднении ошибки компенсируются.

### 2. Random Feature Subspace

При каждом разбиении в дереве выбирается **случайное подмножество признаков** для поиска лучшего разбиения.

```python
# Обычное дерево при каждом разбиении:
best_feature = find_best_among(ALL_FEATURES)

# Random Forest при каждом разбиении:
random_subset = random.sample(ALL_FEATURES, k=sqrt(n_features))
best_feature = find_best_among(random_subset)
```

Для 11 признаков: sqrt(11) ≈ 3 → каждый раз выбираем из 3 случайных признаков.

**Результат:** деревья становятся разнообразными (коррелируют меньше). Разнообразие — источник силы ансамбля.

### 3. Усреднение (Aggregation)

Для регрессии:
```python
final_prediction = mean([tree.predict(x) for tree in trees])
```

Для классификации:
```python
final_prediction = mode([tree.predict(x) for tree in trees])  # голосование
```

## Почему Random Forest намного лучше линейных моделей

| Характеристика | Linear Regression | Random Forest |
|---------------|-------------------|---------------|
| Улавливает нелинейность | ❌ | ✅ |
| Улавливает взаимодействия признаков | ❌ | ✅ |
| Устойчив к выбросам | нет | частично |
| Требует масштабирования | нужно | **не нужно** |
| Интерпретируемость | высокая | средняя |
| RMSE в нашем эксперименте | 4072 с | **309 с** |

Random Forest видит, что "расстояние 5 км в час-пик (9 утра)" — это не просто `5 + 9`, а взаимодействие, которое даёт непропорционально больше времени. Линейная регрессия этого не умеет.

---

## Feature Importance: что RF говорит о признаках

После обучения каждое дерево знает, какие признаки помогали делать разбиения лучше всего (уменьшали ошибку сильнее). Random Forest усредняет это по всем деревьям:

```python
rf.feature_importances_
# distance_km:       0.52  ← главный (половина всей важности!)
# pickup_longitude:  0.11
# dropoff_longitude: 0.09
# hour:              0.08
# pickup_latitude:   0.07
# ...
# vendor_id:         0.01
# passenger_count:   0.01
```

**Это честнее, чем коэффициенты линейной регрессии** — RF измеряет реальное снижение ошибки, а не просто наклон прямой.

## Параметры и что они значат

```python
RandomForestRegressor(
    n_estimators=100,    # количество деревьев
    max_depth=None,      # None = деревья растут до конца (опасно без min_samples_leaf)
    min_samples_leaf=5,  # минимум точек в листе (защита от переобучения)
    max_features='sqrt', # сколько признаков рассматривать при каждом разбиении
    n_jobs=-1,           # использовать все ядра CPU
    random_state=42      # воспроизводимость
)
```

### Сколько деревьев (n_estimators)?

```
10 деревьев  → быстро, но высокая дисперсия
100 деревьев → хорошо (в нашем эксперименте)
500 деревьев → лучше, но в 5x дольше и памяти больше
1000+        → почти не улучшается, но медленнее
```

После ~200-300 деревьев прирост качества становится минимальным (закон убывающей отдачи).

---

## Памяти почему так много (37.7 MB)?

Каждое дерево хранит структуру разбиений. 100 деревьев × средний размер одного дерева ≈ 37 MB.

В production это важно: Random Forest — **объёмная модель**. Если важна компактность, рассмотри Gradient Boosting (6.5 MB в нашем эксперименте при схожей точности).

---

## Out-of-Bag (OOB) Score: бонус Random Forest

Поскольку каждое дерево видело только ~63% данных, оставшиеся 37% можно использовать как "встроенную тест-выборку":

```python
rf = RandomForestRegressor(n_estimators=100, oob_score=True)
rf.fit(X_train, y_train)
print(rf.oob_score_)  # R² на out-of-bag примерах — бесплатная оценка качества
```

Это позволяет оценить качество **без отдельной тест-выборки**. Полезно при малом количестве данных.

---

## Параллельность: почему RF быстрый при n_jobs=-1

Деревья независимы → их можно обучать параллельно:

```
CPU Core 1: Tree_1, Tree_5, Tree_9, Tree_13, ...
CPU Core 2: Tree_2, Tree_6, Tree_10, Tree_14, ...
CPU Core 3: Tree_3, Tree_7, Tree_11, Tree_15, ...
CPU Core 4: Tree_4, Tree_8, Tree_12, Tree_16, ...
```

С `n_jobs=-1` sklearn использует все ядра. Именно поэтому мы добавили этот параметр — без него на 80k строк было бы ~15 секунд вместо 3.7.

---

## Когда использовать Random Forest

✅ Когда нужна **высокая точность** без долгой настройки гиперпараметров  
✅ Когда есть **нелинейные зависимости** и взаимодействия признаков  
✅ Когда нужна **важность признаков** (feature importance)  
✅ Когда данных **достаточно много** (>10k строк)  
✅ Когда не хочется масштабировать признаки  

❌ Когда критична **память** (каждое дерево хранится целиком)  
❌ Когда нужна **интерпретируемость** ("почему именно такой ответ")  
❌ Когда данных мало (<1k строк) — переобучится

## Связь с бэкенд-разработкой

Деплой Random Forest в production:

```python
import pickle

# Сохранение
with open('model.pkl', 'wb') as f:
    pickle.dump(rf, f)

# Загрузка и предсказание
with open('model.pkl', 'rb') as f:
    model = pickle.load(f)

prediction = model.predict([[distance, hour, lat, lon, ...]])[0]
# Время предсказания: ~93 мс на 20k строк (≈ 5 мкс на одну)
```

Предсказание одной точки — микросекунды. Вполне подходит для real-time API.
