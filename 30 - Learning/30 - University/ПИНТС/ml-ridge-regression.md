# Ridge (L2) регрессия — объяснение для бэкендера

> **Контекст:** использована в ПР4 ПИНТС. Результат: RMSE=4072 с, R²=0.47. Ridge показала такое же качество как Linear Regression, но с меньшей памятью (7 MB vs 14 MB). Главная ценность — борьба с мультиколлинеарностью и эффект понижения размерности.

---

## Главная идея

Ridge — это линейная регрессия с наказанием за крупные веса. В отличие от Lasso, Ridge **не обнуляет** веса, а **сжимает** их — делает ближе к нулю, но никогда не равными нулю.

Главная задача Ridge — бороться с **мультиколлинеарностью** (когда признаки сильно коррелируют между собой).

---

## Аналогия: распределение нагрузки

Представь команду из 4 разработчиков, где Вася и Петя делают одно и то же (Senior Backend). Без регуляризации менеджер может сказать: "Вася — 100% нагрузка, Петя — 0%". С Ridge: "Вася — 55%, Петя — 45%". Результат одинаковый, но нагрузка распределена равномерно и стабильнее.

В мире регрессии: если `pickup_latitude` и `dropoff_latitude` коррелируют, Ridge распределит вес между ними, а не "сваливает" всё на один признак.

---

## Как работает L2-регуляризация

К функции ошибки добавляется штраф на квадрат весов:

```
Ridge Loss = MSE + α * Σwᵢ²
```

| Компонент | Смысл |
|-----------|-------|
| `MSE` | обычная ошибка предсказания |
| `Σwᵢ²` | сумма квадратов всех весов (L2-норма) |
| `α` | сила регуляризации |

**Ключевое отличие от Lasso:** штраф `w²` стремится уменьшить вес, но математически не может довести его ровно до нуля (производная `2w` → 0 только при `w → ∞`, но никогда не даёт точный ноль).

---

## Почему Ridge не обнуляет, а Lasso обнуляет

Математически это про форму области допустимых значений:

```
Lasso (L1):              Ridge (L2):
┌───────┐                ┌─────────┐
│ Ромб  │                │  Круг   │
│   ◇   │                │   ○     │
└───────┘                └─────────┘

Оптимальная точка        Оптимальная точка
часто попадает в угол    редко попадает на ось
ромба → точный ноль      → почти ноль, но не ноль
```

Это не интуитивно, но запомни результат: Lasso = обнуляет, Ridge = сжимает.

---

## Мультиколлинеарность: почему это проблема

В нашем датасете NYC Taxi есть 4 координаты:
- `pickup_latitude`, `pickup_longitude`
- `dropoff_latitude`, `dropoff_longitude`

Они **сильно коррелируют** с `distance_km` (которое само из них посчитано по Хаверсину).

Без регуляризации линейная регрессия может дать:

```python
# Нестабильные огромные веса:
pickup_lat:  +500
dropoff_lat: -498
# Разница ≈ 2, но сами числа огромны → нестабильность
```

Маленькое изменение в данных → кардинально другие веса. Модель ненадёжна.

Ridge решает это, штрафуя крупные веса:

```python
# Стабильные умеренные веса:
pickup_lat:  +0.15
dropoff_lat: -0.12
```

---

## Ridge как понижение размерности

Это важная концепция из задания ПР4. Разберём детально.

### Что такое "понижение размерности"

У нас 11 признаков. "Пространство" признаков — 11-мерное. Понижение размерности — уменьшение этого числа, сохраняя максимум информации.

### Как Ridge это делает

Ridge не удаляет признаки (как PCA или Lasso), но **сжимает неважные признаки к нулю**. Фактически модель работает в пространстве меньшей "мощности":

```python
# Linear Regression (нет регуляризации):
distance_km:       +0.85
pickup_longitude:  +0.42
dropoff_longitude: -0.38
pickup_latitude:   +0.31
dropoff_latitude:  -0.29
# Все признаки "орут" — информационный шум

# Ridge (alpha=1.0):
distance_km:       +0.52  ← главный
pickup_longitude:  +0.18  ← умеренный
dropoff_longitude: -0.16  ← умеренный
pickup_latitude:   +0.09  ← тихий
dropoff_latitude:  -0.08  ← тихий
# Главные признаки выделены, шум подавлен
```

Математически говорят: Ridge создаёт **регуляризованную проекцию** на подпространство меньшей нормы.

### Визуальный эффект (из нашего графика `03_ridge_vs_linear_coefs.png`)

```
Признак         Linear Reg.   Ridge (L2)
─────────────────────────────────────────
distance_km         +0.85        +0.52   ← сжат, но остался главным
pickup_lon          +0.42        +0.18   ← сжат сильнее
dropoff_lon         -0.38        -0.16   ← сжат сильнее
...
passenger_count     +0.004       +0.001  ← почти ноль, но не ноль
vendor_id           +0.003       +0.001  ← почти ноль, но не ноль
```

Ridge "тише" говорит о малозначимых признаках, и "громче" — о важных (относительно друг друга).

## Параметр alpha

```python
Ridge(alpha=1.0)  # в нашем эксперименте
```

| alpha | Эффект |
|-------|--------|
| 0.0 | = обычная линейная регрессия |
| 0.01 | слабое сжатие |
| 1.0 | **умеренное сжатие** (хороший default) |
| 100 | сильное сжатие |
| ∞ | все веса → 0, модель предсказывает среднее |

**Как подобрать:** `RidgeCV` в sklearn сам перебирает диапазон alpha и выбирает лучший.

## Когда Ridge лучше, чем Lasso

### Выбирай Ridge, когда:
- Все признаки **реально важны**, просто их нужно сбалансировать
- Признаки **сильно коррелируют** (геопространственные данные, временные ряды)
- Ты хочешь **стабильность** весов (Ridge меньше реагирует на выбросы в данных)

### Выбирай Lasso, когда:
- Многие признаки — мусор, нужен **отбор признаков**
- Важна **разреженность** модели (sparse model)

## Практический пример: когда Ridge спасает

```python
# Датасет: цены квартир в 10 районах Москвы
# Признаки: площадь, этаж, год постройки,
#           расстояние до метро для каждой из 20 ближайших станций

# Проблема: dist_metro_1, dist_metro_2, ... dist_metro_20
# сильно коррелируют между собой

# Без регуляризации: нестабильные веса, плохое обобщение
# Ridge: равномерно распределит вес по всем расстояниям
```

---

## Память vs Linear Regression

В нашем эксперименте Ridge заняла **7.3 MB** против **14.5 MB** у Linear Regression. Это потому что:

1. Sklearn реализует Ridge через иной математический путь (Singular Value Decomposition)
2. Регуляризация упрощает внутреннее представление

Для бэкенда: Ridge — более компактная модель в production.

---

## Техническая деталь: нормальные уравнения

Linear Regression решает:
```
w = (XᵀX)⁻¹ · Xᵀy
```

Ridge добавляет `αI` к матрице перед инвертированием:
```
w = (XᵀX + αI)⁻¹ · Xᵀy
```

Это делает матрицу `(XᵀX + αI)` **гарантированно обратимой**, даже если признаки линейно зависимы (мультиколлинеарны). Именно поэтому Ridge технически более устойчив.
