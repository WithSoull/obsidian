# Lasso (L1) регрессия — объяснение для бэкендера

> **Контекст:** использована в ПР4 ПИНТС. Результат: RMSE=2829 с, R²=0.47. Lasso обнулила `passenger_count`, `vendor_id`, `store_and_fwd_flag` — они не нужны для предсказания.

---

## Главная идея

Lasso — это линейная регрессия с наказанием за большие веса. Но главная особенность: **Lasso умеет обнулять веса ненужных признаков**, то есть автоматически выбирает, какие признаки важны.

Это называется **отбор признаков** (feature selection).

---

## Аналогия: ты наводишь порядок в коде

Представь, что у тебя есть функция с 50 параметрами, из которых реально используются 10. Остальные 40 — мусор, переданный на всякий случай.

```python
# До Lasso: все параметры "влияют"
def calc_duration(distance, hour, lat, lon, passenger_count, vendor_id, ...):
    return (0.52 * distance + 0.03 * hour + 0.001 * passenger_count + 
            0.0005 * vendor_id + ...)

# После Lasso: ненужные обнулены
def calc_duration(distance, hour, lat, lon, ...):
    return (0.52 * distance + 0.03 * hour + 0 * passenger_count + 
            0 * vendor_id + ...)  # → можно убрать эти параметры совсем
```

Lasso автоматически находит те 40 "лишних" параметров и выставляет им нулевой коэффициент.

---

## Почему обычная регрессия не отбрасывает признаки сама

Без регуляризации линейная регрессия стремится использовать все признаки, даже если их вклад минимален. Она говорит: "Я нашла, что `passenger_count` даёт +0.0001 к длительности. Это маленько, но лучше, чем ноль!"

**Проблема:** такая модель:
1. Переобучается на шуме
2. Неинтерпретируема — сложно понять, что важно
3. Не масштабируется — больше признаков = больше мусора

---

## Как работает L1-регуляризация

К функции ошибки добавляется штраф:

```
Lasso Loss = MSE + α * Σ|wᵢ|
```

Читается так:
- `MSE` — обычная ошибка предсказания
- `Σ|wᵢ|` — сумма абсолютных значений всех весов (L1-норма)
- `α` (альфа) — коэффициент, насколько сильно штрафуем за крупные веса

**Аналогия:** у тебя бюджет на аренду серверов. Каждый признак стоит `α` денег в месяц. Если признак зарабатывает меньше `α`, его выгоднее вообще не брать.

### Почему именно ноль, а не просто "маленькое значение"?

Это математический трюк: L1-норма (модуль) имеет "угол" в нуле, который "притягивает" малые веса ровно в ноль. L2-норма (квадрат) такого угла не имеет — она только уменьшает веса, но не обнуляет. Именно поэтому Ridge уменьшает, а Lasso обнуляет.

Визуально:

```
Lasso (L1):         Ridge (L2):
  |                   .·.
  |                  ·   ·
  +---            ---+---
  |                  ·   ·
  |                   `·'

Угол в нуле →      Нет угла →
обнуляет            только уменьшает
```

## Параметр alpha: как выбрать

```python
Lasso(alpha=0.01)  # в нашем эксперименте
```

| alpha | Эффект |
|-------|--------|
| 0.0 | = обычная линейная регрессия (нет штрафа) |
| 0.001 | слабый штраф, почти все признаки сохраняются |
| 0.01 | **умеренный:** обнуляет явно бесполезные |
| 0.1 | сильный: обнуляет много признаков |
| 1.0+ | слишком сильный: модель деградирует |

**Правило выбора:** кросс-валидация (`LassoCV` в sklearn подберёт сам).

## Что мы увидели в ПР4

```
Lasso обнулила эти признаки (вес = 0):
  passenger_count  → 0.0000
  vendor_id        → 0.0000
  store_and_fwd_flag → 0.0000
```

**Интерпретация:** количество пассажиров, ID перевозчика и флаг сохранения записи **никак не влияют** на длительность поездки. Это интуитивно понятно — таксисты едут одинаково быстро независимо от числа пассажиров.

Оставшиеся важные признаки:
```

pickup_longitude:   -0.073  ← зона посадки влияет

...
```

## Аномальный результат: Lasso лучше Linear по RMSE

В нашем эксперименте Lasso (RMSE=2829) оказалась лучше Linear Regression (RMSE=4072). Это произошло потому, что:

1. Обнуленные признаки содержали **шум**, который Linear Regression учила как сигнал
2. Убрав шум, Lasso стала предсказывать "чище"

Это классический пример, когда **меньше признаков = лучше качество**.

## Практическая ценность в production

```python
# Lasso говорит тебе: "Собирай только эти данные"
important_features = [
    'distance_km',   # ← обязательно
    'hour',          # ← обязательно
    'pickup_lat',    # ← обязательно
    'pickup_lon',    # ← обязательно
    # 'passenger_count'  ← не нужно, можно не хранить
    # 'vendor_id'        ← не нужно
]
```

Если ты строишь пайплайн сбора данных для ML-модели, Lasso помогает понять, **какие данные вообще стоит собирать**. Это экономит место в базе, трафик и деньги.

---

## Когда использовать Lasso

✅ Когда признаков **много**, и ты подозреваешь, что многие из них мусор  
✅ Когда нужна **интерпретируемость** — какие признаки вообще важны  
✅ Когда важно **сократить сложность модели** для production  
✅ Когда признаков **больше, чем строк** (высокая размерность)  

❌ Когда все признаки реально важны (Lasso убьёт нужные)  
❌ Когда признаки сильно коррелируют (→ Ridge лучше)  
❌ Когда нужна максимальная точность (→ ансамбли)  

---

## Связь Ridge vs Lasso: когда что выбрать

| Ситуация | Что выбрать |
|----------|-------------|
| Много мусорных признаков | **Lasso** — обнулит их |
| Много скоррелированных признаков | **Ridge** — равномерно уменьшит |
| Не знаешь | **Elastic Net** — комбинация L1+L2 |
