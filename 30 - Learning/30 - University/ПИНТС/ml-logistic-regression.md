# Логистическая регрессия — объяснение для бэкендера

> **Контекст:** использована в ПР4 ПИНТС (бонусное задание) для классификации космических объектов SDSS — GALAXY, STAR, QSO. Результат: Accuracy=0.9546. Уступает Decision Tree (0.9750), но обучается за 0.36 с — быстрее или сравнимо по скорости.

---

## Главная идея

Несмотря на название "регрессия", логистическая регрессия — это алгоритм **классификации**. Она предсказывает не число, а **вероятность принадлежности к классу**.

Связь с линейной регрессией: берём линейную комбинацию признаков и "пропускаем" её через специальную функцию, которая давит результат в диапазон [0, 1].

---

## Аналогия: spam-фильтр

Ты пишешь spam-фильтр. Для каждого письма нужно ответить: спам (1) или не спам (0)?

```python
# Наивная идея: линейная регрессия
score = 0.3 * contains_word_FREE + 0.2 * suspicious_link + ...
# Проблема: score может быть 5.7 или -2.3 — не вероятность!

# Логистическая регрессия: ту же сумму пропускаем через sigmoid
probability_spam = sigmoid(score)
# Теперь: всегда в [0, 1] → это вероятность
```

---

## Sigmoid функция: сердце логистической регрессии

```
σ(x) = 1 / (1 + e^(-x))
```

Что она делает:
```
x = -10  → σ(x) ≈ 0.00005  (почти точно класс 0)
x = -2   → σ(x) ≈ 0.12     (скорее класс 0)
x = 0    → σ(x) = 0.5      (нейтральная граница)
x = +2   → σ(x) ≈ 0.88     (скорее класс 1)
x = +10  → σ(x) ≈ 0.99995  (почти точно класс 1)
```

Визуально:
```
1 |              ·····
  |          ···
  |       ···
0.5|      ·
  |   ···
  |···
0 |___________________
  -5    0    +5
```

S-образная кривая. Линейное в центре, "уплощается" на краях.

---

## Полная формула модели

```
z = w₁·x₁ + w₂·x₂ + ... + wₙ·xₙ + b   # линейная часть
P(класс=1) = σ(z) = 1 / (1 + e^(-z))   # вероятность
```

**Предсказание:**
```python
if P(класс=1) >= 0.5:
    result = 1
else:
    result = 0
```

## Как обучается: функция потерь Log Loss

Для регрессии мы минимизировали MSE (квадратичную ошибку). Для классификации нужна другая функция потерь — **Log Loss** (также называется Binary Cross-Entropy):

```
Loss = -[y·log(ŷ) + (1-y)·log(1-ŷ)]
```

Где `y` — истинный класс (0 или 1), `ŷ` — предсказанная вероятность.

Почему не MSE? Потому что MSE для вероятностей создаёт плохой градиент — модель обучается медленно и застревает. Log Loss "наказывает" уверенные неправильные предсказания сильнее:

```
# Истинный ответ: 1
ŷ = 0.9 → Loss = -log(0.9) = 0.05  (небольшая ошибка)
ŷ = 0.5 → Loss = -log(0.5) = 0.69  (умеренная)
ŷ = 0.1 → Loss = -log(0.1) = 2.30  (большая — была уверена, что 0, а оказалось 1)
ŷ = 0.01→ Loss = -log(0.01)= 4.60  (огромная штраф за уверенную ошибку)
```

## Многоклассовая классификация: Softmax

В нашей задаче 3 класса: GALAXY, STAR, QSO. Для нескольких классов используется обобщение sigmoid — функция **Softmax**:

```python
# Для 3 классов:
scores = [z_galaxy, z_star, z_qso]  # три линейных комбинации
# z_galaxy = w1_g * x1 + w2_g * x2 + ...

probabilities = softmax(scores)
# = [e^z_g / (e^z_g + e^z_s + e^z_q),
#    e^z_s / (e^z_g + e^z_s + e^z_q),
#    e^z_q / (e^z_g + e^z_s + e^z_q)]
#
# Сумма всегда = 1
```

```python
# Пример для одного объекта:
probabilities = [0.82, 0.12, 0.06]
classes       = [GALAXY, STAR, QSO]
# Предсказание: GALAXY (максимальная вероятность)
```

sklearn (`LogisticRegression`) делает это автоматически при `multi_class='auto'`.

---

## Почему Logistic Regression получила 95.46% Accuracy

Датасет SDSS очень хорошо разделяется линейными границами. Физически:

- **Звёзды (STAR):** redshift ≈ 0, яркость в фильтрах u,g,r — характерный профиль
- **Галактики (GALAXY):** redshift от 0.01 до 2, другой спектральный профиль
- **Квазары (QSO):** redshift 0.5–7, очень яркие

Эти три класса достаточно хорошо разделены в 6-мерном пространстве (u, g, r, i, z, redshift), и логистическая регрессия нашла линейные гиперплоскости между ними.

```
Classification Report:
              precision  recall  f1-score
GALAXY           0.96     0.97     0.96
STAR             0.95     1.00     0.97  ← почти идеально!
QSO              0.95     0.87     0.91  ← чуть хуже: квазары ≈ галактики
```

QSO (квазары) сложнее всего — они похожи на галактики в некоторых диапазонах.

## Граница решения: линейная гиперплоскость

Это главное ограничение логистической регрессии — **граница между классами линейна**.

```
2D пример (два признака):
┌─────────────────────────┐
│ * * *                   │
│ * * *  /                │  * = класс A
│ * *  /   o o o          │  o = класс B
│    /   o o o o          │  / = граница (прямая линия)
│  /   o o o o            │
└─────────────────────────┘
```

Если классы нелинейно разделяются (классическая задача XOR), логистическая регрессия не справится. Для этого нужны нелинейные модели.

## Регуляризация в логистической регрессии

По умолчанию sklearn применяет L2-регуляризацию:

```python
LogisticRegression(
    C=1.0,       # обратный коэффициент регуляризации (1/alpha)
    penalty='l2' # по умолчанию Ridge
    # penalty='l1' → Lasso (отбор признаков)
    # penalty='elasticnet' → комбинация
)
```

**Важно:** в sklearn `C` — это обратная сила регуляризации:
- `C=100` → слабая регуляризация (= большой `alpha` у Ridge)
- `C=0.01` → сильная регуляризация

## Интерпретация: коэффициенты и odds ratio

Коэффициенты логистической регрессии можно интерпретировать через **отношение шансов** (odds ratio):

```python
# Если коэффициент для redshift = 2.5:
exp(2.5) = 12.2

# Интерпретация: увеличение redshift на 1 единицу
# увеличивает шанс быть QSO в 12.2 раза
```

Это мощный инструмент для анализа данных в медицине, финансах, социологии.

## Логистическая регрессия в production

Главные преимущества для бэкенда:

**1. Предсказание + вероятность:**
```python
model.predict(['...'])        # → ['GALAXY']
model.predict_proba(['...'])  # → [[0.82, 0.12, 0.06]]
```
Вероятность важна, когда нужно сказать "мы на 82% уверены".

**2. Скорость:**
```
Обучение:    0.36 с на 80k строк
Предсказание: < 1 мс на 1000 объектов
```
Идеально для real-time API.

**3. Размер модели:**
```
Сохранённая модель: несколько KB
(в отличие от Random Forest: десятки MB)
```

**4. Онлайн-обучение:** можно дообучать на новых данных без переобучения с нуля (`SGDClassifier` с `loss='log_loss'`).

---

## Когда использовать логистическую регрессию

✅ Когда нужна **вероятность** (не просто класс, а "насколько уверена")  
✅ Когда нужна **интерпретируемость** (что влияет на решение)  
✅ Когда важна **скорость** обучения и предсказания  
✅ Когда данных **мало** (не переобучится)  
✅ Как **baseline** в задачах классификации  
✅ Когда классы **линейно разделимы**  

❌ Когда граница между классами **нелинейна** (→ RF, GB)  
❌ Когда признаки **взаимодействуют сложно** (→ нейросети, GB)  
❌ Когда нужна максимальная точность

## Связь: регрессия vs логистическая регрессия

| Характеристика | Линейная регрессия | Логистическая регрессия |
|---|---|---|
| Задача | Предсказать число | Предсказать класс |
| Выход | Любое число | Вероятность [0, 1] |
| Функция активации | нет (тождественная) | Sigmoid / Softmax |
| Функция потерь | MSE | Log Loss (Cross-Entropy) |
| Метрика | RMSE, MAE, R² | Accuracy, F1, AUC-ROC |

Фундаментально — это одно семейство моделей. Логистическая регрессия — это линейная с sigmoid "на выходе".
