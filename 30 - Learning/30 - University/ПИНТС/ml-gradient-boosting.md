# Gradient Boosting — объяснение для бэкендера

> **Контекст:** использован в ПР4 ПИНТС. Результат: RMSE=317 с, R²=0.76 — почти как Random Forest, но компактнее (6.5 MB vs 37.7 MB). Обучение заняло 26 секунд — в 7 раз дольше RF.

---

## Главная идея

Random Forest берёт 100 деревьев и строит их **параллельно, независимо**. Gradient Boosting строит деревья **последовательно**: каждое следующее дерево исправляет ошибки предыдущего.

Это как итеративная отладка: запустил, нашёл баги, исправил, запустил снова — и так 200 раз.

---

## Аналогия: отладка сложного бага командой

**Random Forest:** 100 разработчиков смотрят код независимо и голосуют. Большинство скажет правильный ответ.

**Gradient Boosting:** 200 разработчиков смотрят код последовательно. Первый делает общий анализ. Второй смотрит только на то, что первый пропустил. Третий — на то, что пропустили первый и второй. Каждый следующий специализируется на ошибках предшественников.

---

## Пошаговый алгоритм

### Шаг 0: Начинаем с простейшего предсказания

```python
# Первое "дерево" — просто среднее всех значений
initial_prediction = mean(y_train)
# Для поездок: ~900 секунд
```

### Шаг 1: Считаем остатки (residuals)

```python
residuals = y_train - initial_prediction
# Поездка была 1800 с, предсказали 900 с → остаток = +900
# Поездка была 300 с, предсказали 900 с  → остаток = -600
```

**Остатки** — это то, что модель не смогла объяснить. Gradient Boosting следующим деревом будет предсказывать именно эти остатки.

### Шаг 2: Обучаем дерево на остатках

```python
tree_1.fit(X_train, residuals)
# Дерево учится: "в каких ситуациях я ошибаюсь на +900?"
```

### Шаг 3: Обновляем предсказание

```python
# learning_rate (η) — насколько доверяем новому дереву
prediction_2 = initial_prediction + learning_rate * tree_1.predict(X_train)
# = 900 + 0.1 * 900 = 990 секунд
```

### Шаг 4: Повторяем для новых остатков

```python
residuals_2 = y_train - prediction_2
tree_2.fit(X_train, residuals_2)
prediction_3 = prediction_2 + learning_rate * tree_2.predict(X_train)
```

### Итог после 200 деревьев:

```python
final_prediction = (
    initial_prediction
    + η * tree_1.predict(X)
    + η * tree_2.predict(X)
    + ...
    + η * tree_200.predict(X)
)
```

## Почему "Gradient"?

Это "градиентный" спуск, но в пространстве функций, а не параметров.

В обычном градиентном спуске мы обновляем числа (веса нейросети):
```
w := w - learning_rate * gradient_of_loss(w)
```

В Gradient Boosting мы обновляем **функцию предсказания**:
```
F := F + learning_rate * (новое_дерево_для_остатков)
```

Остатки для квадратичной ошибки (MSE) — это буквально **отрицательный градиент** функции потерь. Поэтому и называется "Gradient" Boosting.

Не нужно понимать математику градиентного спуска глубоко. Запомни: каждое следующее дерево делает шаг в сторону уменьшения ошибки.

## Ключевые параметры

```python
GradientBoostingRegressor(
    n_estimators=200,     # количество деревьев (шагов)
    learning_rate=0.1,    # размер каждого шага
    max_depth=4,          # глубина каждого дерева (неглубокие!)
    random_state=42
)
```

### learning_rate vs n_estimators: компромисс

```
learning_rate=0.1, n_estimators=200  → хорошо (наш выбор)
learning_rate=0.01, n_estimators=2000 → лучше, но в 10x дольше
learning_rate=0.5, n_estimators=40   → быстро, но хуже точность
```

**Правило:** маленький learning_rate + много деревьев = лучше, но медленнее.

### Почему деревья неглубокие (max_depth=4)?

В Random Forest деревья глубокие (часто без ограничений). В Gradient Boosting деревья намеренно **маленькие и слабые** — их называют "weak learners". Каждое по отдельности — плохой предсказатель. Но 200 таких слабых деревьев в сумме дают сильный результат.

```
Дерево с max_depth=4: 2^4 = 16 листьев максимум
Дерево с max_depth=None (RF): тысячи листьев
```

Маленькие деревья:
- Меньше переобучаются на конкретных примерах
- Лучше обобщают
- Занимают меньше памяти (6.5 MB vs 37.7 MB у RF)

---

## Почему GB медленнее RF: принципиальная разница

| | Random Forest | Gradient Boosting |
|--|---------------|-------------------|
| Порядок | Параллельный | Последовательный |
| Зависимость | Деревья независимы | Дерево N зависит от дерева N-1 |
| CPU | все ядра | одно ядро (по умолчанию) |
| Время (80k строк) | **3.7 с** | 26.5 с |

RF можно распараллелить (`n_jobs=-1`). Классический GB — нет, потому что нужны остатки предыдущего дерева.

**Решение:** `HistGradientBoostingRegressor` (sklearn) или `XGBoost`/`LightGBM` — умеют параллелить и работают в 10–100x быстрее.

---

## GB vs RF: когда что лучше

| Ситуация | Выбор |
|----------|-------|
| Нужна максимальная точность | **GB** (обычно чуть точнее) |
| Ограничена память в production | **GB** (меньше размер модели) |
| Нужна скорость обучения | **RF** (параллельный) |
| Нужна устойчивость к шуму | **RF** (усредняет) |
| Данных мало | **RF** (меньше переобучается) |
| Данных много + много времени | **XGBoost/LightGBM** (modern GB) |

В нашем эксперименте: RF=309 сек RMSE, GB=317 сек RMSE. Разница 2.5% — практически одинаково.

## Overfitting в Gradient Boosting

GB легче переобучается, чем RF. Признаки переобучения:

```python
# Обучающая ошибка падает, тестовая растёт:
train_rmse: [500, 350, 200, 100, 50, 20, ...]  # всё лучше
test_rmse:  [480, 340, 310, 320, 330, 345, ...] # начала расти!
```

**Защита:**
- Уменьши `learning_rate` и увеличь `n_estimators`
- Ограничь `max_depth` (у нас 4 — хорошо)
- Добавь `subsample=0.8` (стохастический GB — использует 80% данных на каждом шаге)
- Добавь `min_samples_leaf=10`

## Modern Gradient Boosting: XGBoost, LightGBM, CatBoost

Классический `GradientBoostingRegressor` из sklearn — медленный. В production используют:

| Библиотека | Скорость | Особенность |
|-----------|----------|-------------|
| **XGBoost** | 10–50x быстрее | параллельный, regularization |
| **LightGBM** | 50–100x быстрее | leaf-wise growth, экономит память |
| **CatBoost** | 20–50x быстрее | автоматически обрабатывает категории |

Это те же идеи, но оптимизированные. В реальных проектах и на Kaggle используют именно их.

```python
# Установка и использование LightGBM (почти идентично sklearn):
pip install lightgbm

import lightgbm as lgb
model = lgb.LGBMRegressor(n_estimators=500, learning_rate=0.05)
model.fit(X_train, y_train)
```

## Feature Importance в GB

GB тоже умеет считать важность признаков:

```python
gb.feature_importances_
# distance_km:       0.48
# pickup_longitude:  0.13
# hour:              0.10
# dropoff_latitude:  0.09
# ...
```

GB и RF дают схожую картину важности — это хороший знак, что результат достоверен.

---

## Когда использовать Gradient Boosting

✅ Когда нужна **максимальная точность** предсказания  
✅ Когда важна **компактность модели** (меньше памяти, чем RF)  
✅ Когда участвуешь в **соревнованиях Kaggle** (GB доминирует)  
✅ Когда данных **много** (>50k строк)  

❌ Когда нужна **скорость обучения** (→ RF)  
❌ Когда данных **мало** (переобучится легче RF)  
❌ Когда важна **интерпретируемость** (→ линейные модели)  
❌ Когда нет времени на настройку гиперпараметров
