**Расшифровка:** Breadth-First-Search

# Общие сведения

- Работает с невзвешенными *направленными* [[30 - Learning/10 - Foundation/40 - Algo/113 - Структуры данных/Graphs|графами]]
- Решает следующие задачи:
	1) существует ли путь из А в Б?
	2) как выглядит кратчайший путь из А в Б? (т. е. ищет длину кратчайшего пути)
- В своей основе использует две структуры - очевидно [[30 - Learning/10 - Foundation/40 - Algo/113 - Структуры данных/Graphs|граф]] и [[30 - Learning/10 - Foundation/40 - Algo/113 - Структуры данных/Queue|очередь]]
- Алгоритмическая сложность: $O(E+V)$

# Описание алгоритма

Вот у нас есть, граф, начальная точка А и точка Б, которую мы хотим найти. Сначала мы просмотрим всех соседей точки А, и для каждого этого соседа, мы внесем в очередь новых людей, а именно соседей соседа А, так мы с сделаем с каждой точкой.

![[99 - Meta/02 - Медиа/Pasted image 20231019074128.png]]

Тогда алгоритм действий для каждой точки выглядит вот так:
1) Достаем эту точку из очереди
2) Посмотреть проходили ли мы ее раньше (иначе мы попадем в бесконечный цикл)
3) Добавить ее соседей в очередь
# Реализация

- Python
	Из "Грокаем Алгоритмы" (ищут продавца манго в соц сетях)
	```python 
	from collections import deque 
	
	graph = {...}
	
	def BFS(name):
		search_queue = deque()
		search_queue += graph[name]
		searched = []                                  # список тех по кому уже прошлись
		while search_queue:
			person = search_queue.popleft()            # достаем точку из очереди (пункт 1)
			if not person in searched:                 # проверяем, проходили ли ее раньше (пункт 2)
				if person_is_seller(person):
					print(person + " is mango seller")
					return person
				else:
					searched.append(person)
					search_queue += graph[person]      # добавляем ее соседей (пункт 3)
		
		return -1 
	```


# Асимптотика

Если мы прошлись по всей сети, то мы прошли через все ребра, значит алгоритмическая сложность как минимум $O(E)$, Е - количество ребер

Мы также храним вершины в очереди, добавление в очередь это $О(1)$, значит для всего графа это будет $О(V)$, V - количество вершин.

Тогда итоговая алгоритмическая сложность составляет $O(E+V)$
