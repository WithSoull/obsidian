# Описание алгоритма
![[99 - Meta/02 - Медиа/Pasted image 20231019230903.png]]

У нас есть три мапы: сам граф со ценами, цены (которые будут меняться потом) и родители (чтобы отметить родителей через который этот кратчайший путь и лежит), также есть массив обработанных вершин.

В чем главный смысл? Во время обхода графа мы, меняем цены, делая их минимальными, в примере выше, в А можно добраться сначала только за 6, но когда мы посмотрим на соседей Б, мы увидим, что до А можно добраться быстрее за 2 + 3 = 5

Алгоритм действий:
1) Пока остаются не обработанные узлы повторять цикл
2) Взять необработанный узел, ближайший к началу
3) Обновить стоимость его соседей, если это необходимо
	4) Обновить таблицу родителей, если обновляли соседей
5) Отмечаем узел обработанным, и возвращаемся к первому пункту

- Python
	Из "Грокаем Алгоритмы" (ищут продавца манго в соц сетях)
	
	```python 
	def find_lowest_cost_node(costs, visited):  
    min_cost = float("inf")  
    lowest_cost_node = None  
    for node in costs:  
        if node not in visited:  
            min_cost = min(min_cost, costs[node])  
            lowest_cost_node = node  
  
    return lowest_cost_node  
  
  
def Dijkstra(graph, costs, parents, start, end):  
    processed = set()  
    node = find_lowest_cost_node(costs, processed)  
    while node is not None:  
        cost = costs[node]  
        neighbors = graph[node]  
  
        for name, neighnor_cost in neighbors:  
            new_cost = cost + neighnor_cost  
            if costs[name] > new_cost:  
                costs[name] = new_cost  
                parents[name] = node  
  
        processed.add(node)  
        node = find_lowest_cost_node(costs, processed)  
  
    return costs[end]  
  
  
def main():  
    graph = {  
        "start": {  
            "A": 6,  
            "B": 2,  
        },  
        "A": {"end": 3},  
        "end": None,  
    }  
    costs = {  
        "A": 6,  
        "B": 2,  
        "end": float("inf"),  
    }  
    parents = {  
        "A": "start",  
        "B": "start",  
        "end": None,  
    }  
  
    print(Dijkstra(graph, costs, parents, "start", "end"))  
  
  
main()
```

# Асимптотика

Если мы прошлись по всей сети, то мы прошли через все ребра, значит алгоритмическая сложность как минимум $O(E)$, Е - количество ребер

Мы также храним вершины в очереди, добавление в очередь это $О(1)$, значит для всего графа это будет $О(V)$, V - количество вершин.

Тогда итоговая алгоритмическая сложность составляет $O(E+V)$
