### Небольшой исторический контекст - ASN.1
- Стандартизирован в **1984 году**
- Используется для определения сетевых протоколов
- Бинарное кодирование (DER) применяется в SSL сертификатах (X.509)
- Поддерживает schema evolution через tag numbers (как Protocol Buffers/Thrift)
- **Недостатки**: сложность, плохая документация
- Не рекомендуется для новых приложений
### Недостатки Схем (Avro, Thrift, Protobuf) перед JSON/XML
Бинарные форматы менее содержательны по сравнению с JSON/XML, потому что вторые могут содержать дополнительные ограничения по типу:
- Строка должна соответсвовать regex
- Число должно лежать в диапозоне от 0 до 100
### Преимущества Схем (Avro, Thrift, Protobuf) перед JSON/XML
###### 1. Компактность
Значительно компактнее "binary JSON/XML" вариантов, в основном засчет того, что можно опускать имена полей в закодированных данных.
###### 2.Документация
Схема = по факту есть форма документации, которая актуальна (поскольку требуется для декодирования).
###### 3. Контроль Совместимости
Можно сделать БД совместимости версий схем. Она позволяет проверять обратную и прямую совместимость.
###### 4. Генерация Кода
- Полезно для статически типизированных языков
- Позволяет type checking на этапе компиляции
