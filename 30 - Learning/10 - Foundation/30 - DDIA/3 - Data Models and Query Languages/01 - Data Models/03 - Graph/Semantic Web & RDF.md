## Концептуальные основы

### Semantic Web: Видение vs Реальность

**Исходная идея**: Websites публикуют данные в машиночитаемом формате, создавая глобальную «базу знаний всего» через RDF-стандарты. Tim Berners-Lee назвал это **Giant Global Graph** — сетью связанных данных в противоположность document-ориентированной WWW.

**Историческая перспектива**: Semantic Web пережил период **перегретых ожиданий в начале 2000-х**, что привело к цинизму в отношении его практической реализации. Проект страдал от:
- Головокружительного множества аббревиатур и сложных стандартов
- Чрезмерной сложности веб-ориентированных технологий
- Разрыва между теоретическими возможностями и практическим применением

**Современное состояние (2024-2025)**: Несмотря на изначальные трудности, Semantic Web технологии нашли широкое применение в корпоративных системах. Большие организации в Media & Publishing, Healthcare, Life Sciences и Financial Services активно используют RDF triple stores для управления структурированными и неструктурированными данными.

### RDF как фундамент

**Независимость от Semantic Web**: Triple stores **не равны** Semantic Web — ключевой пример **Datomic**, который использует модель триплетов, но не претендует на связь с Semantic Web. Первичная инновация Datomic — immutability и time travel, а не сам факт использования триплетов.

**Практическая ценность**: RDF триплеты эффективны как **внутренняя модель данных** приложений, даже без публикации данных в Semantic Web. Это позволяет:
- Гибко развивать схемы данных без миграций
- Эффективно представлять разреженные и многозначные атрибуты
- Интегрировать данные из разнородных источников

## Технические детали RDF

### Форматы сериализации

#### Сравнение основных форматов RDF

| Формат | Человеко-читаемость | Компактность | Поддержка инструментами | Расширение | Применение |
|---------|-------------------|--------------|------------------------|------------|------------|
| **Turtle/TTL** | Высокая | Высокая | Отличная | .ttl | Общего назначения |
| **RDF/XML** | Низкая | Низкая | Отличная | .rdf/.xml | Исторический стандарт |
| **N-Triples** | Средняя | Низкая | Отличная | .nt | Простой обмен |
| **N3 (Notation3)** | Высокая | Высокая | Хорошая | .n3 | Логические правила |
| **JSON-LD** | Высокая | Средняя | Отличная | .jsonld | Веб-интеграция |
| **N-Quads** | Средняя | Низкая | Хорошая | .nq | Множественные графы |
| **TriG** | Высокая | Высокая | Хорошая | .trig | Множественные графы |

#### Характеристики форматов

**Turtle/N3** — предпочтительный человеко-читаемый формат:
- Компактный синтаксис с сокращениями для общих префиксов
- Совместимость с SPARQL syntax patterns
- Поддержка всех RDF функций без ограничений XML

**RDF/XML** — исторический стандарт:
- Многословный, но универсально поддерживаемый
- Ограничения XML препятствуют кодированию некоторых RDF графов
- Сложность для ручного редактирования

**JSON-LD** — современный веб-формат:
- Прямая совместимость с JSON
- Идеален для REST API и JavaScript приложений
- Поддержка контекстов для сокращения verbosity

### URI и пространства имён

**Глобальная идентификация**: Субъект, предикат и объект триплета часто представлены как URIs для обеспечения глобальной уникальности. Например:
- `<http://my-company.com/namespace#within>` vs `<http://other.org/foo#within>`
- Избежание конфликтов значений при объединении данных
