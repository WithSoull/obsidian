## Структура
Единица это JSON-документ (или подобный, в MongoDB есть BSON - это бинарный вид JSON), который описывает какой-то объект без особой структуры

| Плюсы                                                                                                                                                                           | Минусы                                                 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| Легче маппить объекты приложения -> меньше impedance mismatch, которым может страдать [[SQL#^5446c6|SQL]] | Нет строгой схемы, возможны ошибки при эволюции данных |
| Лучше локальность: один запрос вытаскивает весь профиль                                                         | Большие проблемы с Many-To-One отношениями             |
| Поддержка [[MapReduce|MapReduce]]                                                                                |                                                        |
|                                                                                                                                                                                 |                                                        |

## Many-To-One отношения
![[99 - Meta/02 - Медиа/Pasted image 20251009172333.png]]
В [[public/30 - Learning/10 - Foundation/30 - DDIA/3 - Data Models and Query Languages/01 - Data Models/01 - Relational/SQL|SQL]] эта проблема входит в часть **нормализации**, что плохо ложиться на документо-ориентированную модель. В **relational** базах норма ссылаться на строки в других таблицах по ID, потому что легко делать *JOIN*. А в **document** базах с *JOIN*, дела обстоят печально, их либо нет(MongoDB),  либо слабая поддержка(RethinkDB / CouchDB). 
Есть опция написать JOIN на уровне приложения, а не на уровень базы данных. Особенно в этом случае список регионов небольшой и медленно меняется, так что приложение может хранить in-memory список регионов. Но все равно: даже если сначала удобно хранить данные в одном JSON-документе без связей (join-free), со временем приложение обрастает фичами, и данные становятся **всё более связанными**. Например: 
1) Организации и школы
	- Изначально: организация/школа = строка
	- Новые фичи → отдельные сущности (страницы компаний/университетов)
	- Профиль хранит ссылки на них (ID), а не строки
2) Рекомендации
	- Один пользователь пишет отзыв другому
	- Отзыв должен подтягивать имя/фото автора
	- Если фото изменилось → должно обновиться везде
	- Нужно хранить ссылку на профиль автора, а не дублировать данные
