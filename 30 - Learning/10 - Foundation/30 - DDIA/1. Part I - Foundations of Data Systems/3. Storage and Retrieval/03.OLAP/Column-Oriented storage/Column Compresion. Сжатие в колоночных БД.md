Благодаря сжатию мы можем уменьшить требование к пропускной способности диска (*disk throughput*)

![[99 - Meta/02 - Медиа/Pasted image 20251030105442.png]]

Присмотримся к последовательным набору данных на этой картинке, они тут часто *повторяюстя* - очень хороший знак для *сжатия*. Есть разные техники для сжатия, например *bitmap encoding*.
![[99 - Meta/02 - Медиа/Pasted image 20251030105721.png]]

Из-за того, что число уникальных значение в одной колонке малое по сравнению с количеством всех этих значение (то бишь размер всего столбца).

Мы можем взять N уникальных значений и составить N *separate bitmaps*(битовая маска): 
- 1 bitmap - 1 уник значение.
- Количество битов = количество строк внутри одного bitmap
- Тут мы ставим 1 если строка содержит это значение, 0 - если не содержит. 
Тут лучше внимательно посмотреть на схему выше, чтобы понять получше.

По итогу у нас получаются очень разряженные последовательности бит. Почти все они 0. Поэтому мы можем использовать *run-length encoding(RLE)*: 9 нулей, 1 единицы, остальные 0.

###### Запросики
1) Тут нам нужно подгрузить битмапы для product_sk = 30, 68, 69; а затем посчитать *побитовое ИЛИ* для 3 битмап, что делается очень быстро.
 ```sql
 WHERE product_sk IN (30, 68, 69):
```
2) Тут нам надо подгрузить битмапы для product_sk = 31 и store_sk = 3; а затем посчитать *побитовое И* для 2 битмап, что делается очень быстро.
``` sql
 WHERE product_sk = 31 AND store_sk = 3;
```
