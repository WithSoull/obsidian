>[!danger] Принцип работы
> - Данные распределяются по логическим уровням. Каждый уровень это "слой" данных, совокупность нескольких SSTables  
> - Каждый уровень содержит непересекающиеся диапазоны ключей.  

- *Level 0* - несколько маленьких SSTables (сброс memtable). **Единственный слой в котором могут пересекаться ключи**
- *Level 1* - множество SSTable, ключи в которых не пересекаются внутри между собой в рамках одного уровня
- *Level 1+* - same
###### Инкрементное продвижение
- Данные из L0 объединяются с SSTable из L1, покрывающий нужный диапазон ключей, на выходе получаем новые SSTable для L1.
- Данные из L1 объединяются cо всеми SSTable из L2, чьи диапазоны пересекаются

Что мы получаем, за счет такого слияния: 
1) Ключ может существовать только в одной SSTable в рамках одного слоя.
2) Частая компакция, но объединяется мало SSTable (на одну "верхнеуровневую" SSTable 10-12 "низкоуровневых" SSTable)
###### Read Amplification
Тут для чтения нужно проверить по одной SSTable на каждом уровне (*> 0*). Быстрое и предсказуемое чтение, а это означает низкую амплитуду чтения
###### Write Amplification
Из-за того, что данные перезаписываются много раз по мере продвижения мы получаем высокую амплитуду записи
###### Disk space
Частая компакция снижают пиковую нагрузку за счет распределения и повторяющихся/удаленных данных становиться сильно меньше.
