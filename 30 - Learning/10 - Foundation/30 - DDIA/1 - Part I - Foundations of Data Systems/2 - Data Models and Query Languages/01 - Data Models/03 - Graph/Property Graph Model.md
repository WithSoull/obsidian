Это одна из варицаций data graph model в базах данных.
#### Структура
- Каждая вершина состоит из:
	1) Уникальный идентификатор
	2) Множество исходящих ребер
	3) Множество входящих ребер
	4) Свойства в key-value формате
- Каждое ребро состоит из:
	1) Уникальный идентификатор
	2) Вершина (начало)
	3) Вершина (конец)
	4) Подпись (label) которая описывает тип отношения между двумя вершинами
	5) Свойства в key-value формате

#### Реализация в реляционной схеме (пример)
Все это дело в целом можно запихнуть в *relational* модель (свойства можно положить в Postgres JSON например):
``` sql
CREATE TABLE vertices (
    vertex_id integer PRIMARY KEY,
    properties json
);

CREATE TABLE edges (
    edge_id integer PRIMARY KEY,
    tail_vertex integer REFERENCES vertices (vertex_id),
    head_vertex integer REFERENCES vertices (vertex_id),
    label text,
    properties json
);

CREATE INDEX edges_tails ON edges (tail_vertex);
CREATE INDEX edges_heads ON edges (head_vertex);
```

^1a4bda

#### Ключевые особенности
1) Любые две вершины можно соединить. То есть нет никакой схемы, в которой было бы описано, что можно соединять, а что нет.
2) По заданной вершине можно найти все исходящие и входящие ребра, и соответсвенно обойти граф). Поэтому мы проиндексировали `edges_tails` и `edges_heads`.
3) Используя разные метки (label) для разных видов отношений можно хранить разного рода информацию в одном графе, поддерживая чистую модель данных при этом.

#### Пример использования
- Моделирование сложных географических структур в разных странах
- Хранение социальных связей и личной информации (например, аллергии и зависимости продуктов от аллергенов)
- Возможность легко добавлять новые типы связей без изменения общей структуры
