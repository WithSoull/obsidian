## 4. Пакет C — схемы

### C0. Инструмент: draw.io для всех семи рисунков

**Почему не Graphviz.** Он сам раскладывает узлы, поэтому:

- дорожки (`cluster`) получаются разной высоты и на разном уровне (#100);
- подписи рёбер наезжают друг на друга (#105);
- линии идут наискосок и сквозь блоки;
- ортогональная трассировка `splines=ortho` не поддерживает подписи рёбер.

**Почему draw.io:**

- координаты задаются явно, по сетке;
- рёбра трассируются ортогонально (`edgeStyle=orthogonalEdgeStyle`);
- есть библиотеки BPMN (`mxgraph.bpmn.*`), UML-состояний, блок-схем, компонентов и таблиц ER;
- автор может открыть `.drawio` в приложении и подвинуть блоки руками;
- экспорт делается из командной строки.

**Установка и экспорт:**

- поставить `brew install --cask drawio` (согласовать с автором);
- экспорт: `/Applications/draw.io.app/Contents/MacOS/draw.io -x -f png -s 3 -b 10 -o images/<name>.png images/src/<name>.drawio`;
- скрипт `images/src/render.sh` экспортирует все схемы.

**Исходники.** Каноничный исходник — `images/src/<name>.drawio` в несжатом XML. Генерировать его скриптом или писать вручную — на усмотрение агента. Скрипт-генератор не должен перезаписывать файлы, которые автор правил руками. После миграции `.dot` удалить. `deployment` и `dfd` в тексте не используются: проверить через `grep` и удалить вместе с PNG.

**Запасной вариант**, если экспорт draw.io без окна не работает: BPMN через bpmn.io (`npx bpmn-to-image`, BPMN 2.0 XML с координатами), остальное через PlantUML (Java есть). Требования к стилю те же.
